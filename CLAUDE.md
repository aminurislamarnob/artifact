# CLAUDE.md

Artifact is a WordPress block theme (full site editing) for company websites, aimed at WordPress.org. Default look is black. Requires WordPress 6.9+ (the work process section uses `core/accordion`) and PHP 7.4+. `theme.json` schema version 3. Text domain `artifact`, domain path `/languages`.

Local site: `https://woocommerce.test` (Herd root `/Users/aiarnob/Herd/woocommerce`; this repo is its `wp-content/themes/artifact`). Run WP-CLI there with `--url=https://woocommerce.test`, because its `wp-config.php` builds the site URL from the request host. No build step. Activate the theme and load the site.

## Architecture

`theme.json` is the only token source. Patterns, parts, and templates consume presets (`var(--wp--preset--…)` or `var:preset|…`). Do not copy hex into markup or CSS.

- `functions.php` loads the text domain, requires `inc/tgmpa.php`, and filters `hooked_block_types` so WooCommerce's mini cart and account blocks stay out of the header. Nothing else: no block style registration, no supports core already gives block themes.
- `inc/tgmpa.php` recommends Contact Form 7 (Contact page) and Brevo (`mailin`, footer newsletter) through the bundled TGM Plugin Activation 2.6.1 (`inc/class-tgm-plugin-activation.php`, translation calls switched to the `artifact` text domain and its own text domain loading removed). Neither is required or auto-activated, and the notice is dismissable. The theme must work fully without them.
- `templates/front-page.html` is a `<main>` of `wp:pattern` references in order: hero, features, about, fun-facts, services, a wide separator, work-process, team, testimonials, latest-articles, project-cta.
- `parts/header.html` and `parts/footer.html` only reference `artifact/header` and `artifact/footer`. Those patterns hold the markup, are bound to their template part areas, and have `Inserter: no`. Both brand the site with core `site-logo` plus `site-title` in `.artifact-site-brand`; CSS hides the title once a logo is set, so a new site shows its own name, never a theme logo. Their "Start a Project" links are `mailto:`, the footer's Privacy Policy link appears only when the site has a published privacy page, and footer social icons link to each network's home page. The footer's Subscribe Us column links the RSS feed (`get_feed_link()`); site owners swap it for a Brevo form in a Shortcode block, which the readme explains.
- The header menu is an empty `<!-- wp:navigation /-->`, so core shows the site's newest saved menu or its pages. Do not hard-code menu links. The current page link (`aria-current="page"`) is primary-coloured.
- Pages other than the front page ship as starter page patterns (`Block Types: core/post-content`, `Post Types: page, wp_template`) built from section patterns, plus the `page-no-title` custom template (header, `post-content`, footer) so the pattern can supply the H1. `artifact/page-services` is page-hero, services-grid, a wide separator, work-process, a wide separator, project-cta. `artifact/page-about` is page-hero, a team photo, brands, values, fun-facts-grid, a wide separator, team, a wide separator, project-cta; its client names are text, not logos, so users can swap in their own. `artifact/page-portfolio` is page-hero, portfolio-grid (eight cards in alternating wide and narrow rows; only the title links), a wide separator, project-cta. `artifact/page-contact` is its own hero (same structure as page-hero, with contact copy), contact-info, a wide separator, project-cta. `artifact/contact-info` holds the contact details, a Follow Us card of core social links, and a message panel (`.artifact-contact-form`) whose "Send Inquiry" button is a `mailto:` link. `artifact/page-hero` labels the page with a `post-title` block at `level: 0`.
- Repeatable page types get a custom template for structure plus a starter pattern for the body, like Twenty Twenty-Five. Each service is a child page of Services using the `page-service-details` template: header, `artifact/hidden-service-hero` ("Service Details" label and the page title as the H1), `post-content` (full width, `spacing|20` side padding), a wide separator, `artifact/project-cta`, footer. `artifact/page-service-details` is the body: intro, photo, approach, features and problems, two photos, deliverables, next steps. Each project is a child page of Portfolio using the `page-portfolio-details` template: header, `post-content` (full width, `spacing|20` side padding), a wide separator, `artifact/project-cta`, footer. Its facts (category, client, date, location) differ per project, so `artifact/page-portfolio-details` carries the whole hero (a `post-title` at `level: 1`, an introduction and the facts) followed by a photo, about, challenges and solutions, two photos, process and results. Text a template shows goes in a hidden pattern, never in the HTML.
- Forms are plugin territory. Patterns use core blocks only: no plugin blocks, no shortcodes (a CF7 form is identified by a per-site hash, and a missing plugin prints the shortcode as text). Site owners swap the message panel's text and button for a Contact Form 7 block, and the footer's feed link for a Brevo Shortcode block; `readme.txt` explains how.
- `index`, `archive`, and `search` are main-query loops (blog cards with featured image, author avatar, date, time to read) with pagination and the hidden `artifact/hidden-no-results` pattern; their headings come from `artifact/hidden-blog-heading`, `artifact/hidden-archive-heading` and `artifact/hidden-search`. `404` uses `artifact/hidden-404` with a search. `single` has title, meta, featured image, content, terms, a two-post latest articles query under `artifact/hidden-more-articles-heading`, and threaded, paginated comments. `page` is title and content.
- Templates and parts carry no text of their own (a unit test checks): every visible string, block label and button text lives in a pattern so it can be translated.
- Hidden patterns are named `hidden-*.php` and have `Inserter: no`. Every other pattern uses core pattern categories (`services`, `banner`, `featured`, …); do not register theme categories.
- Card links with repeated text ("Learn More") carry a `screen-reader-text` span naming their target, so link names are unique.
- Theme CSS lives in `theme.json` `styles.css`, scoped to `artifact-*` classes and core block classes (post content, comments, query pagination, forms). It uses presets and `rgba()`, never hex. Breakpoints are 1024px, 781px, and 600px. Respect `prefers-reduced-motion`. Contact Form 7 output is styled through CF7's own classes (`.wpcf7`, `.wpcf7-form-control`, `.wpcf7-submit`, `.wpcf7-not-valid-tip`, `.wpcf7-response-output`), with selectors that outrank CF7's stylesheet, which stays loaded. Brevo forms (`.sib_signup_form`) share the CF7 field and submit rules; Brevo colours its alerts with ID selectors, so the theme's alert rules use `!important`, and the core Shortcode block's `wpautop` adds `<br>` and empty `<p>` the theme hides. In the footer the Brevo email field sits beside a square arrow submit. Form control rules are always scoped (to `#commentform`, `.wpcf7` or `.sib_signup_form`), never bare `input`, `select` or `textarea`. Inside `.artifact-contact-form` the form is a two-column grid; children holding a textarea, the submit button or the response span both columns. The submit arrow is the `arrow_outward` Material Symbol inlined as a data URI, since `theme.json` CSS cannot reference theme files. Blog article typography (`.wp-block-post-content`, `.entry-content`) is wrapped in `:where(body:not(.page-template-page-no-title):not(.page-template-page-service-details):not(.page-template-page-portfolio-details))` so it never restyles pattern-built pages. Add new pattern-built page templates to that list.
- Block style variations are JSON in `styles/blocks/` (files with `blockTypes`, currently `button-rounded.json`). No theme style variation JSON.
- `style.css` is the theme header only, with no rules.
- Fonts are self-hosted Poppins WOFF2 (400, 500, 600, 700) in `assets/fonts/` with `OFL.txt`. No TTF, no font CDN.
- Images in `assets/images/` are Figma vector artwork (GPL as part of the theme), Material Symbols, and CC0 photos. Every icon (`icon-*.svg`, `stars-rating.svg`) is a Material Symbol (Apache 2.0) listed by file and symbol name in the `readme.txt` Material Symbols entry. Figma icon layers named `fi_<number>` are Flaticon downloads: never export them. Every photo is a CC0 StockSnap photo credited with its page URL in `readme.txt` (a unit test checks): the service, company and portfolio photos, and the people photos the Figma file showed without a licence (`hero-illustration-main.webp`, `about-team.jpg`, `work-desk.jpg`, the greyscale `team-*.jpg` cards and the `story-wade-*.jpg` testimonial portraits). The hero photo is masked to the design's notched shape and stored as WebP to keep transparency small. StockSnap's CDN serves photos up to 960px wide. Do not use Unsplash, Pixabay, Freepik, Flaticon, Shutterstock, or other non-GPL asset services. No remote images or scripts at runtime.
- No theme JavaScript. Interactive sections use core blocks (the accordion uses core's own script) and CSS.
- `.distignore` keeps dev files (`.agents`, `.claude`, `tests`, configs, `CLAUDE.md`, `AGENTS.md`, `README.md`) out of the release zip.

## WordPress.org rules

- Escape all PHP output: `esc_html__()`/`esc_html()` between tags, `esc_attr__()`/`esc_attr()` in attributes, `esc_url()` for URLs, `wp_kses_post()` for translatable markup. No raw echoes.
- Every translatable string uses the `artifact` text domain and must be in `languages/artifact.pot`. Regenerate it with `wp i18n make-pot . languages/artifact.pot`.
- Prefix functions, constants, handles, image sizes, and custom CSS classes with `artifact_` or `artifact-`.
- Plugin territory is off limits: no custom post types, taxonomies, custom blocks, shortcodes, or roles. Do not remove core hooks or hide the admin bar.
- Spell "WordPress" with a capital P.

## Tokens

Keep these slugs. `main-bg` is the page surface. Use primary as text only where contrast meets AA. Add a slug only when a colour cannot map.

- Colors: `primary`, `secondary`, `main-bg`, `light-bg`, `dark-bg`, `heading-color`, `text-white`, `text-color`, `link-color`, `border`
- Font sizes: `small|medium|large-paragraph`, `small|medium|large-title`, `heading-01`…`heading-06`, `button-large`, `button-small`
- Spacing: `10`, `20`, `30`, `50`, `60`, `70`, `100`
- Font family: `poppins`
- Layout: `contentSize` 800px, `wideSize` 1170px

`appearanceTools` and `useRootPaddingAwareAlignments` are on. Core default palette, gradients, duotone, spacing sizes, and font sizes are off.

## theme.json cache

WordPress caches compiled global styles. If an edit does not show, hard-refresh. Site Editor customizations in `wp_global_styles` override `theme.json`.

## Tests

`composer test:unit` (files only), `composer test:integration` (needs the `artifact_tests` MySQL database, which it wipes), `npm run test:e2e` (Playwright and axe-core; needs Artifact active on `WP_BASE_URL`, default `https://woocommerce.test`, and `WP_PATH` for WP-CLI, default `~/Herd/woocommerce`; it runs 1 worker because Herd's PHP pool returns 502s under parallel load). E2E global setup creates and then deletes its own posts, pages (one built from `artifact/page-services`, one from `artifact/page-about`, one from `artifact/page-portfolio`, one from `artifact/page-contact`, a child service using the Service Details template, and a child project using the Portfolio Details template), with Contact Form 7 active a CF7 form and a Contact page holding it in its message panel (the CF7 specs skip otherwise), category, administrator, and a navigation menu, which the header shows because it is the newest. When you add a token slug, pattern or template, update the expected lists in `tests/phpunit/unit` so the suite keeps guarding the contract. See `README.md` for setup.

Also run `wp theme-check run artifact` (Theme Check plugin) and, from the WordPress root, `WP_BASE_URL=https://woocommerce.test bash wp-content/themes/artifact/.claude/skills/wp-theme-reviewer/scripts/theme-unit-test.sh verify` (Theme Unit Test settings and endpoints; without `WP_BASE_URL` its WP-CLI calls get no site URL and the endpoint checks fail). The script's `import` and `settings` commands change the site's options, permalinks, and plugins, so ask first.
